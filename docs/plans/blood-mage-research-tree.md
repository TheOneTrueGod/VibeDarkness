# Blood Mage Research Tree + Abilities — Implementation Plan

Goal: a new **Blood Mage** archetype — ranged/mid-range, spends its own HP as a resource, manipulates blood/shielding. Black-and-red visual identity that's deliberately **blended/misty**, never a stark two-tone split — reads as life, blood, and death together. Three abilities granted one-per-node in a linear 3-node research tree: **Blood Mend** (0301, ally heal costing HP), **Burst** (0302, cone damage costing HP, modeled on Cone of Light), **Protect** (0303, ally shield buff costing HP).

This also requires a few pieces of genuinely new shared engine infrastructure that don't exist yet: an HP-cost-to-cast mechanic (gate + manual deduction), a shield-buff damage-absorption pipeline, and an `onBlock` hook fired when a shield fully soaks a hit.

## Plan-level decisions (locked)

- **HP-cost gate:** default `'requireSurplus'` (must have `hp > cost` to cast); per-ability override `'floorAtOne'` (always castable; deduction clamped so it can't drop the caster below 1 HP). **Blood Mend uses `'floorAtOne'`** (so a dying Blood Mage can still land one last desperate heal); **Burst and Protect use the strict default**.
- **Protect targets an ally via the same crosshairs (`unitRangeHitbox` + `filter:'ally'` + `allowMiss:false`) as Blood Mend** — not self-only.
- **One shared "blood mist" VFX helper module** (`abilities/bloodMageVfx.ts`) is reused by all three abilities rather than bespoke one-offs.
- **Design-intent doc lives once, in `card_defs/03_blood_mage/AGENTS.md`** (visual identity + risk/reward feel) — every ability file and the research tree file gets a one-line reference comment pointing at it instead of restating the intent inline.
- **Shield-vs-armour consumption order:** shields consumed **before** earth-core armour (shields are per-cast/temporary; armour is longer-lived).
- **Burst:** damage **18** flat (matches Cone of Light's own damage — Cone of Light is already significantly above-average for a cone, so Burst sits at that bar rather than exceeding it), **max 4 targets** (vs. Cone of Light's 6), **3 max uses**, recharges on **1 stamina** (`staminaCharge`).
- **`Unit.takeDamage`/`applyDamageToUnit` stay byte-for-byte unchanged** (thin wrappers around new `takeDamageDetailed`/`applyDamageToUnitDetailed`) to avoid touching ~100 existing call sites. A `docs/TODO.md` entry (Step 3) tracks migrating callers to the detailed API over time, in batches, rather than doing it all now.
- **`onBlock` wiring only covers damage routed through `tryDamageOrBlock`** (melee/projectile `CastBehaviours`, which covers Burst). Direct/AoE `unit.takeDamage()` call sites still get HP-pool shield absorption (universal, in `unitDamage.ts`) but won't fire `onBlock` — acceptable, since the only described interaction (Burst vs. Protect) is melee/cone-based.
